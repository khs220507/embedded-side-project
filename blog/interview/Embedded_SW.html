Embedded Study Note

STM32 Embedded SW: 프로젝트 기반 면접 핵심

실제 구현 코드와 보드 검증 경험에서 선별한 면접 질문과 답이다.

InterruptDMAADCTimer·PWM핀·검증

1. Interrupt에서 긴 작업을 하지 않은 이유는?

HAL_TIM_PeriodElapsedCallback()은 timerSampleRequested = 1U만 설정한다. 긴 ADC 변환·PWM 갱신·UART 출력은 Main Loop로 분리해 다른 Interrupt의 지연을 줄였다.

2. volatile을 왜 사용했는가?

Timer Interrupt와 DMA Callback이 쓰고 Main Loop가 읽는 Flag에 사용했다. 컴파일러 최적화로 변경을 놓치지 않게 하지만, 원자성과 복잡한 동기화를 보장하는 것은 아니다.

3. UART에 DMA와 ReceiveToIdle을 사용한 이유는?

DMA가 메모리와 UART Peripheral 사이의 데이터 이동을 맡아 CPU 부담을 줄인다. HAL_UARTEx_ReceiveToIdle_DMA()는 길이가 고정되지 않은 명령 문자열을 Idle 시점에 처리한다.

4. __WFI()를 사용한 이유는?

DMA 완료를 기다릴 때 Busy-wait 대신 Interrupt가 올 때까지 대기해 CPU를 불필요하게 소모하지 않도록 했다.

5. ADC Polling을 선택한 이유와 한계는?

CdS를 500ms마다 한 번 읽는 현재 조건에는 단순한 Polling이 충분했다. 더 빠른 연속 측정이나 실시간 작업이 많아지면 ADC DMA 또는 Interrupt를 검토해야 한다.

6. Timer를 왜 두 개로 분리했는가?

TIM2는 500ms 측정 시점만 만들고, TIM1은 1kHz PWM을 계속 출력한다. 느린 주기 작업과 고속 PWM을 분리해 역할과 설정을 명확히 했다.

7. PWM으로 LED 밝기를 어떻게 조절했는가?

Prescaler = 83, Period = 999로 1kHz PWM을 만들고, __HAL_TIM_SET_COMPARE()로 Duty Cycle을 바꿨다. 밝기는 깜빡이는 횟수가 아니라 HIGH 시간 비율로 조절된다.

8. PA8을 Alternate Function으로 설정한 이유는?

GPIO_AF1_TIM1으로 PA8을 TIM1 Channel 1 PWM 출력에 연결했다. 일반 GPIO 출력만으로는 Timer PWM 파형을 핀으로 내보낼 수 없다.

9. 빌드 성공과 보드 검증 완료를 구분한 이유는?

빌드 성공은 소스와 링크 설정만 확인한다. 배선, 전원, 핀 설정, 센서와 UART 통신은 실제 보드에서 별도로 확인해야 한다.

STM32 HAL: GPIO, UART, DMA와 ADC 제어

HAL의 기본 구조와 현재 코드에서 사용한 GPIO, UART, DMA, ADC API를 정리한다.

HAL이란?

HAL은 Hardware Abstraction Layer의 약자로, 하드웨어 추상화 계층을 의미한다. STM32의 레지스터를 직접 조작하지 않고도 주변장치를 제어할 수 있도록 STMicroelectronics가 제공하는 드라이버 함수 모음이다.

HAL을 사용하는 이유

레지스터를 직접 제어하면 주변장치마다 주소와 bit 위치를 계산해야 한다. HAL은 이 작업을 함수와 구조체로 감싸 의미 있는 이름으로 하드웨어를 제어하게 해준다.

HAL_GPIO_WritePin(GPIOB, GPIO_PIN_5, GPIO_PIN_SET);
HAL 함수 호출
GPIOB 레지스터 제어
PB5 HIGH
LED 켜짐
  • 함수 이름으로 코드의 목적을 파악하기 쉽다.
  • 레지스터 주소와 bit 계산을 반복하지 않아도 된다.
  • GPIO, UART, Timer 등을 일관된 구조로 사용할 수 있다.
  • 정해진 상태값으로 동작 결과를 확인할 수 있다.

HAL을 사용하더라도 Pin 설정, 통신 속도, 데이터 길이 같은 하드웨어 조건은 개발자가 정확히 지정해야 한다.

Handle 구조체

HAL은 주변장치의 설정과 현재 상태를 Handle 구조체로 관리한다.

UART_HandleTypeDef huart2;

huart2.Instance = USART2;
huart2.Init.BaudRate = 115200;
huart2.Init.WordLength = UART_WORDLENGTH_8B;
huart2.Init.StopBits = UART_STOPBITS_1;
huart2.Init.Parity = UART_PARITY_NONE;
huart2.Init.Mode = UART_MODE_TX_RX;
HAL_UART_Transmit(&huart2,
                  message,
                  sizeof(message) - 1U,
                  HAL_MAX_DELAY);

&huart2를 통해 HAL은 USART2의 설정과 현재 동작 상태를 확인하고 갱신할 수 있다.

HAL 함수의 반환값

여러 HAL 함수는 HAL 드라이버에 미리 정의된 HAL_StatusTypeDef로 실행 결과를 반환한다. HAL_OK 역시 사용자가 만든 값이 아니라 HAL에서 제공하는 상태값이다.

typedef enum
{
    HAL_OK      = 0x00U,
    HAL_ERROR   = 0x01U,
    HAL_BUSY    = 0x02U,
    HAL_TIMEOUT = 0x03U
} HAL_StatusTypeDef;
반환값의미
HAL_OK정상 완료
HAL_ERROR동작 중 오류 발생
HAL_BUSY주변장치가 다른 작업 수행 중
HAL_TIMEOUT제한 시간 안에 완료되지 않음

UART Interrupt 수신을 시작할 때도 반환값을 검사한다.

if (HAL_UART_Receive_IT(&huart2, &receivedByte, 1U) != HAL_OK)
{
    Error_Handler();
}

HAL_OK이면 수신이 정상적으로 등록된 것이다. 이후 문자가 도착하면 USART2 IRQ와 HAL_UART_RxCpltCallback()을 통해 완료를 알린다.

UART DMA에서 사용하는 HAL

03_UART_DMA에서는 두 개의 DMA_HandleTypeDef로 USART2 RX와 TX의 DMA 설정과 상태를 관리한다.

DMA_HandleTypeDef hdma_usart2_rx;
DMA_HandleTypeDef hdma_usart2_tx;

__HAL_RCC_DMA1_CLK_ENABLE()

DMA1에 Peripheral Clock을 공급하는 HAL Macro다.

__HAL_RCC_DMA1_CLK_ENABLE();

STM32는 사용하지 않는 주변장치의 Clock을 꺼 전력 소모를 줄인다. DMA Register를 설정하거나 전송을 시작하기 전에 DMA1 Clock을 먼저 활성화해야 한다.

HAL_NVIC_SetPriority()와 HAL_NVIC_EnableIRQ()

DMA Stream Interrupt의 우선순위를 정하고 NVIC에서 해당 IRQ를 활성화한다.

HAL_NVIC_SetPriority(DMA1_Stream5_IRQn, 0, 0);
HAL_NVIC_EnableIRQ(DMA1_Stream5_IRQn);

HAL_NVIC_SetPriority(DMA1_Stream6_IRQn, 0, 0);
HAL_NVIC_EnableIRQ(DMA1_Stream6_IRQn);
함수핵심 인자역할
HAL_NVIC_SetPriority()IRQ, Preemption Priority, SubpriorityIRQ 우선순위 설정
HAL_NVIC_EnableIRQ()IRQNVIC에서 해당 Interrupt 허용

Stream5는 USART2 RX DMA, Stream6은 USART2 TX DMA가 사용한다. 두 IRQ 모두 Priority를 0, 0으로 설정했다.

MX_DMA_Init()은 STM32CubeMX가 만든 Project 초기화 함수이며 HAL 함수가 아니다. 내부에서 DMA Clock과 NVIC 설정을 위해 위 HAL Macro와 함수를 호출한다.

HAL_DMA_Init()

DMA Handle에 지정한 Stream, Channel, 전송 방향, 주소 증가 방식과 데이터 단위를 실제 DMA Register에 적용한다.

if (HAL_DMA_Init(&hdma_usart2_rx) != HAL_OK)
{
    Error_Handler();
}
항목의미
&hdma_usart2_rx초기화할 RX DMA Handle 주소
반환값HAL_OK, HAL_ERROR 등의 HAL_StatusTypeDef

HAL_UART_Transmit_DMA()

Memory Buffer의 데이터를 DMA로 UART에 송신하도록 시작한다.

HAL_UART_Transmit_DMA(&huart2,
                      uartDmaTxBuffer,
                      chunkSize);
인자의미

함수는 송신을 시작한 뒤 반환하고, DMA와 UART 송신이 끝나면 HAL_UART_TxCpltCallback()이 호출된다. 현재 _write()는 Callback이 Flag를 바꿀 때까지 __WFI()로 기다리므로 호출 방식은 동기식이다.

__WFI()는 HAL이 아니라 CMSIS-Core가 제공하는 CPU Intrinsic이다. 자세한 내용은 CMSIS 학습 문서에서 관리한다.

HAL_UARTEx_ReceiveToIdle_DMA()

정해진 Buffer 크기만큼 DMA 수신을 시작하면서 UART IDLE 상태도 감지한다.

HAL_UARTEx_ReceiveToIdle_DMA(&huart2,
                             uartDmaRxBuffer,
                             UART_RX_BUFFER_SIZE);
인자의미
&huart2수신에 사용할 UART Handle
uartDmaRxBufferDMA가 저장할 Memory Buffer
UART_RX_BUFFER_SIZE수신 가능한 최대 바이트 수

Buffer가 가득 차거나 RX 선이 IDLE 상태가 되면 실제 수신 크기와 함께 HAL_UARTEx_RxEventCallback()이 호출된다. 현재 RX DMA는 DMA_NORMAL이므로 Callback에서 다음 수신을 다시 등록한다.

__HAL_DMA_DISABLE_IT()

특정 DMA Interrupt를 비활성화하는 HAL Macro다.

__HAL_DMA_DISABLE_IT(&hdma_usart2_rx, DMA_IT_HT);

현재 코드는 Half Transfer Interrupt인 DMA_IT_HT를 사용하지 않으므로 비활성화하고 IDLE 또는 Transfer Complete 이벤트만 처리한다.

HAL_DMA_IRQHandler()와 Callback

DMA Stream IRQ에서 HAL_DMA_IRQHandler()를 호출하면 HAL이 발생한 Flag를 확인하고 완료 또는 오류 처리로 전달한다.

void DMA1_Stream5_IRQHandler(void)
{
    HAL_DMA_IRQHandler(&hdma_usart2_rx);
}

RX는 DMA1 Stream5, TX는 DMA1 Stream6 IRQ에서 각각 자신의 DMA Handle을 전달한다.

HAL_UART_IRQHandler()

USART IRQ에서 호출해 RXNE, IDLE, TC, 오류 등의 UART Interrupt 원인을 확인하고 HAL의 해당 처리로 전달한다.

void USART2_IRQHandler(void)
{
    HAL_UART_IRQHandler(&huart2);
}

현재 DMA 수신에서는 IDLE 감지, DMA 송신에서는 UART의 최종 Transmission Complete 처리에 사용된다. DMA Stream IRQ와 USART2 IRQ는 서로 대체하지 않으며 전송 단계에 따라 둘 다 사용될 수 있다.

Callback은 애플리케이션에서 구현하지만 이름과 호출 시점은 HAL이 정의한다.

void HAL_UARTEx_RxEventCallback(
    UART_HandleTypeDef *huart,
    uint16_t size);

void HAL_UART_TxCpltCallback(
    UART_HandleTypeDef *huart);
  • HAL_UARTEx_RxEventCallback(): IDLE 또는 DMA 수신 완료 시 실제 수신 크기를 전달한다.
  • HAL_UART_TxCpltCallback(): DMA 기반 UART 송신 완료를 알린다.

ADC에서 사용하는 HAL

04_ADC_CdS에서는 ADC_HandleTypeDef hadc1에 ADC1 설정과 상태를 저장한다. PA0는 ADC1_IN0 Analog Input이며, 12-bit 단일 변환을 Software Trigger로 실행한다.

HAL_ADC_Init()과 HAL_ADC_ConfigChannel()

HAL_ADC_Init(&hadc1);

channelConfig.Channel = ADC_CHANNEL_0;
channelConfig.Rank = 1;
channelConfig.SamplingTime = ADC_SAMPLETIME_84CYCLES;
HAL_ADC_ConfigChannel(&hadc1, &channelConfig);

HAL_ADC_Init()은 Handle 설정을 ADC1에 적용하며 내부에서 HAL_ADC_MspInit()을 호출해 ADC1 Clock과 PA0 Analog Mode를 준비한다. 이때 __HAL_RCC_ADC1_CLK_ENABLE() Macro가 ADC1 Peripheral Clock을 활성화한다. HAL_ADC_ConfigChannel()은 변환할 Channel, 순서와 Sampling Time을 정한다.

Polling 단일 변환

HAL_ADC_Start(&hadc1);
HAL_ADC_PollForConversion(&hadc1, 10U);
rawValue = HAL_ADC_GetValue(&hadc1);
HAL_ADC_Stop(&hadc1);

현재 ADC 경로는 Interrupt와 Callback을 사용하지 않으므로 ADC IRQ도 활성화하지 않는다. 구현과 Debug 빌드는 완료했지만 CdS 모듈을 연결한 보드 값은 아직 확인하지 않았다.

HAL과 직접 레지스터 제어의 관계

HAL과 직접 레지스터 제어는 서로 다른 하드웨어를 사용하는 방식이 아니다. HAL 함수도 최종적으로 같은 STM32 레지스터를 읽고 쓴다.

방식흐름
HAL 사용함수 호출 → HAL 내부 코드 → 레지스터
직접 제어사용자 코드 → 레지스터

현재 단계에서는 HAL로 GPIO, UART와 ADC의 동작 흐름을 먼저 익히고, 직접 레지스터 제어는 내부 구조를 더 깊게 학습할 때 다룬다.

배운 점

  • HAL은 STM32 주변장치를 함수와 구조체로 제어하게 해주는 하드웨어 추상화 계층이다.
  • HAL 함수 내부에서도 최종적으로 MCU 레지스터를 읽거나 쓴다.
  • 주변장치 설정과 상태는 Handle 구조체에 저장한다.
  • 주변장치를 초기화한 다음 HAL 동작 함수를 호출해야 한다.
  • 여러 HAL 함수는 정해진 상태값으로 결과를 반환한다.
  • __HAL_LINKDMA()는 UART Handle과 DMA Handle을 양방향으로 연결한다.
  • UART DMA 함수는 전송을 시작한 뒤 IRQ와 Callback으로 완료를 알린다.
  • ADC Polling 변환은 시작, 완료 대기, 결과 읽기, 정지 순서로 수행한다.

한 줄 정리

STM32 HAL은 레지스터 제어를 함수, Macro와 Handle 구조체로 감싸 GPIO, UART, DMA와 ADC를 일관된 방식으로 사용할 수 있게 해주는 드라이버 계층이다.

Timer에서 사용하는 HAL

05_Timer_Sampling은 TIM_HandleTypeDef htim2에 TIM2의 설정과 상태를 저장한다. Prescaler 8399, Period 4999로 500ms마다 Update Event를 만든다.

HAL_TIM_Base_Init(&htim2);
HAL_TIM_Base_Start_IT(&htim2);

void TIM2_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim2);
}

HAL_TIM_Base_Init()은 Counter 설정을 적용하고 HAL_TIM_Base_MspInit()을 호출한다. 현재 MSP Init은 __HAL_RCC_TIM2_CLK_ENABLE()로 Clock을 켜고 NVIC에서 TIM2_IRQn을 활성화한다. HAL_TIM_Base_Start_IT()은 Counter와 Update Interrupt를 시작한다.

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        timerSampleRequested = 1U;
    }
}

HAL_TIM_IRQHandler()가 Update Flag를 처리하면 HAL이 Callback을 호출한다. Callback은 Flag만 설정하고 ADC Polling·LED·UART 출력은 Main Loop에서 처리한다.

PWM에서 사용하는 HAL

06_PWM_LED에서는 TIM_HandleTypeDef htim1이 TIM1 PWM 설정과 상태를 저장한다. HAL_TIM_PWM_Init()은 PWM 동작을 초기화하고 HAL_TIM_PWM_MspInit()을 통해 TIM1 Clock을 활성화한다.

HAL_TIM_PWM_ConfigChannel(&htim1, &channelConfig, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);

__HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, pulse);

HAL_TIM_PWM_ConfigChannel()은 Channel 1의 PWM Mode, Polarity, 초기 Compare 값을 설정하고, HAL_TIM_PWM_Start()는 출력을 시작한다. PA8은 HAL_TIM_MspPostInit()에서 GPIO_AF1_TIM1 Alternate Function으로 설정되어 TIM1_CH1 신호를 출력한다.

__HAL_TIM_SET_COMPARE()는 Timer를 멈추지 않고 Compare Register를 갱신하는 HAL Macro다. 현재 코드는 TIM2 Update Interrupt 뒤 Main Loop에서 CdS ADC 원시값 0~4095를 0~1000으로 변환해 전달한다. PWM 자체는 Interrupt나 Callback을 사용하지 않는다.

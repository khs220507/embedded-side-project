STM32 C: 포인터와 임베디드 자료형

GPIO와 UART 구현에서 실제로 사용한 포인터, 구조체, 상태 머신과 고정 폭 정수형을 정리한다.

전체 목차포인터구조체와 레지스터enum 상태 머신고정 폭 정수형32-bit와 64-bit한 줄 정리

GPIO 포트를 전달하는 포인터

서로 다른 GPIO Port에 연결된 LED를 하나의 함수로 제어하기 위해 Port는 포인터로, Pin은 값으로 전달했다.

static void LED_On(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)
{
    LED_AllOff();
    HAL_GPIO_WritePin(GPIOx, GPIO_Pin, GPIO_PIN_SET);
}

LED_On(GPIOB, GREEN_LED_Pin);
LED_On(GPIOA, RED_LED_Pin);

GPIO_TypeDef *GPIOx는 GPIO 주변장치 레지스터가 있는 주소를 저장한다. 호출 시 전달한 GPIOB와 GREEN_LED_Pin은 함수 안의 GPIOx와 GPIO_Pin에 각각 대응한다.

매개변수전달하는 내용방식
GPIO_TypeDef *GPIOxGPIO 레지스터의 주소포인터
uint16_t GPIO_PinPin 선택 비트값값
  • 포인터는 일반 데이터뿐 아니라 하드웨어 레지스터의 위치도 전달한다.
  • Port를 포인터 매개변수로 받으면 하나의 함수를 GPIOA, GPIOB 등에 재사용할 수 있다.
  • 선언의 *는 주소를 저장하는 포인터라는 뜻이다.

구조체로 표현한 GPIO 레지스터

typedef struct
{
    __IO uint32_t MODER;
    __IO uint32_t OTYPER;
    __IO uint32_t OSPEEDR;
    __IO uint32_t PUPDR;
    __IO uint32_t IDR;
    __IO uint32_t ODR;
    __IO uint32_t BSRR;
    __IO uint32_t LCKR;
    __IO uint32_t AFR[2];
} GPIO_TypeDef;

typedef struct는 관련된 레지스터를 하나의 구조체로 묶고 자료형 이름을 GPIO_TypeDef로 정한다. STM32에서는 별도 변수를 만드는 대신 실제 GPIO 시작 주소를 이 구조체 형태로 바라본다.

멤버오프셋역할
MODER0x00입력·출력·대체 기능 모드
OTYPER0x04Push-Pull·Open-Drain
OSPEEDR0x08출력 속도
PUPDR0x0CPull-up·Pull-down
IDR0x10입력 상태
ODR0x14출력 상태
BSRR0x18Pin SET·RESET
LCKR0x1C설정 잠금
AFR[2]0x20, 0x24UART 등의 대체 기능

__IO와 실제 주소 연결

__IO는 읽고 쓸 수 있는 하드웨어 레지스터임을 나타내며 내부적으로 volatile 성격을 가진다. 하드웨어가 값을 바꿀 수 있으므로 컴파일러가 접근을 임의로 제거하거나 캐시하지 못하게 한다.

#define GPIOA ((GPIO_TypeDef *) GPIOA_BASE)
#define GPIOB ((GPIO_TypeDef *) GPIOB_BASE)

GPIOB->ODR;  /* GPIOB 시작 주소 + ODR 오프셋 0x14 */

->는 구조체 포인터가 가리키는 대상의 멤버에 접근하는 연산자다. 구조체 배치를 실제 레지스터 배치와 맞췄기 때문에 주소 계산 대신 의미 있는 멤버 이름을 사용할 수 있다.

enum과 switch 상태 머신

typedef enum
{
    LED_STATE_IDLE,
    LED_STATE_RUNNING,
    LED_STATE_WARNING,
    LED_STATE_ERROR,
    LED_STATE_COUNT
} LED_State;

static LED_State currentState = LED_STATE_IDLE;

currentState = (LED_State)((currentState + 1) % LED_STATE_COUNT);

상태값은 선언 순서대로 0부터 시작한다. LED_STATE_COUNT는 실제 상태가 아니라 상태 개수 4를 나타내며, 나머지 연산으로 IDLE → RUNNING → WARNING → ERROR → IDLE 순환을 만든다.

switch (state)
{
    case LED_STATE_IDLE:
        LED_On(GREEN_LED_GPIO_Port, GREEN_LED_Pin);
        break;
    case LED_STATE_RUNNING:
        LED_On(BLUE_LED_GPIO_Port, BLUE_LED_Pin);
        break;
    case LED_STATE_WARNING:
        LED_On(YELLOW_LED_GPIO_Port, YELLOW_LED_Pin);
        break;
    case LED_STATE_ERROR:
        LED_On(RED_LED_GPIO_Port, RED_LED_Pin);
        break;
    default:
        LED_AllOff();
        break;
}

break는 선택된 동작 후 switch를 종료한다. default는 예상하지 못한 값에서 모든 LED를 끄는 안전 처리다.

고정 폭 정수형

uint8_t message[] = "Hello STM32!\r\n";
static void LED_On(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin);
uint32_t lastDebounceTime = 0U;

stdint.h의 uint8_t, uint16_t, uint32_t는 unsigned 정수의 bit 수가 이름에 명확히 드러나는 자료형이다.

자료형크기와 범위현재 용도
uint8_t1byte, 0~255UART byte 배열
uint16_t2byte, 0~65,535GPIO Pin 선택 비트
uint32_t4byte, 0~4,294,967,295HAL_GetTick() 시간

UART, GPIO와 시간값

UART는 byte 단위로 데이터를 전송하므로 uint8_t 배열이 적합하다. GPIO Port의 Pin 0~15는 16개의 서로 다른 bit로 표현되므로 Pin 값은 uint16_t를 사용한다. HAL_GetTick()은 밀리초 단위의 uint32_t를 반환하므로 이전 시간도 같은 자료형으로 저장한다.

HAL_UART_Transmit(&huart2,
                  message,
                  sizeof(message) - 1U,
                  HAL_MAX_DELAY);

if ((HAL_GetTick() - lastDebounceTime) >= BUTTON_DEBOUNCE_MS)
{
    /* debounced button event */
}

U 접미사와 sizeof()

0U와 1U의 U는 상수를 unsigned int로 취급한다는 뜻이다. sizeof(message)에는 C 문자열 끝의 \0도 포함되므로, 화면에 표시할 문자만 전송할 때 1U를 뺀다.

  • 고정 폭 정수형은 레지스터, 통신 데이터, 시간처럼 크기가 중요한 코드의 의도를 분명하게 한다.
  • 계산하는 값끼리 자료형을 맞추면 signed/unsigned 혼합을 줄일 수 있다.
  • sizeof()는 배열 전체의 byte 크기를 계산한다.

DS-01에서 확인한 32-bit·64-bit와 구조체 크기

구현 목표

09_DataStructures_Basic의 CommandBuffer 선언을 기준으로 배열 크기, size_t, CPU bit 수, 구조체 크기의 관계를 구분한다.

#define COMMAND_BUFFER_CAPACITY 16U

typedef struct
{
    char data[COMMAND_BUFFER_CAPACITY];
    size_t length;
} CommandBuffer;

32-bit와 64-bit

보통 PC 설정에서 x86은 32-bit, x64는 64-bit CPU·실행 환경을 뜻한다. x32는 일반적인 CPU 이름으로 쓰지 않으므로, 이 문서에서는 32-bit 환경을 x86 또는 32-bit라고 부른다.

실행 환경주소·포인터 크기이 학습과의 관계
PC x64 (MSVC)보통 8bytesize_t도 보통 8byte
STM32F401RE (32-bit ARM Cortex-M4)4bytesize_t도 4byte

size_t는 배열 길이와 메모리 크기를 표현하는 unsigned 자료형이다. 정확한 크기는 컴파일 대상에 따라 달라진다.

CommandBuffer 크기

char는 1byte이므로 data[16]은 항상 16byte다. 전체 구조체에는 length도 포함된다.

PC x64의 일반적인 계산:  data[16] 16byte + size_t 8byte = 24byte
STM32F401RE의 일반적인 계산: data[16] 16byte + size_t 4byte = 20byte

멤버 순서와 CPU 정렬 규칙에 따라 Padding byte가 들어갈 수도 있다. 정확한 크기는 대상 환경에서 sizeof(CommandBuffer)로 확인한다. 현재 DS-01은 이 값을 출력하지 않았으므로 위 수치는 실행 출력이 아닌 자료형 크기 계산이다.

빌드 상태와 배운 점

  • PC x64 MSVC Build Tools에서 CMake 빌드와 CTest 1개가 통과했다.
  • STM32CubeIDE ARM GCC에서 문법·경고 검사를 통과했다.
  • 배열 크기와 구조체 전체 크기는 다르며, 같은 C 코드도 대상 환경에 따라 size_t 크기가 달라질 수 있다.

한 줄 정리

포인터와 구조체로 하드웨어 레지스터를 표현하고, enum 상태 머신과 고정 폭 정수형으로 임베디드 코드의 의미와 데이터 크기를 명확하게 만들었다.

STM32 CMSIS: __WFI()로 Interrupt 대기

UART DMA 송신 완료를 기다릴 때 사용하는 Cortex-M4의 Wait For Interrupt 명령을 정리한다.

기본 개념구현 목표핵심 코드코드 설명주의 사항실행 결과배운 점한 줄 정리

기본 개념

CMSIS(Cortex Microcontroller Software Interface Standard)는 ARM Cortex-M Processor를 공통된 이름과 Interface로 사용할 수 있게 하는 표준 계층이다. STM32 HAL이 UART와 DMA 같은 STM32 주변장치를 다룬다면 CMSIS-Core는 Cortex-M CPU Register와 명령을 다룬다.

구현 목표

03_UART_DMA의 _write()에서 DMA 송신이 끝날 때까지 CPU가 빈 반복문을 계속 실행하지 않도록 __WFI()를 사용한다.

핵심 코드

while (uartDmaTxComplete == 0U)
{
    __WFI();
}

GCC용 CMSIS Header에는 다음과 같이 정의되어 있다.

#define __WFI() __ASM volatile ("wfi":::"memory")

__WFI()는 C 표준 함수나 STM32 HAL 함수가 아니다. CMSIS가 제공하는 Compiler Intrinsic Macro이며 ARM의 WFI(Wait For Interrupt) 명령을 생성한다.

코드 설명과 동작 흐름

uartDmaTxComplete가 0U이면 DMA 송신이 아직 끝나지 않은 상태다. CPU는 __WFI()를 실행하고 Interrupt가 발생할 때까지 대기한다.

DMA 송신 시작
__WFI() 대기
DMA 또는 USART2 IRQ
TX Callback에서 완료 Flag 설정

CPU를 깨운 Interrupt가 반드시 UART TX 완료라는 보장은 없다. 따라서 깨어난 뒤 while 조건으로 완료 Flag를 다시 확인한다.

주의 사항

  • DMA와 USART2 IRQ가 활성화되어 있어야 TX 완료 Callback이 실행된다.
  • Interrupt가 비활성화되어 완료 Flag가 바뀌지 않으면 _write()가 계속 대기한다.
  • 현재 코드는 불필요한 반복 연산은 줄이지만 호출자가 송신 완료까지 기다리는 동기식 구조다.
  • 완전한 Non-blocking 송신에는 TX Queue나 Ring Buffer가 필요하다.

실행 결과

__WFI()가 포함된 03_UART_DMA의 Debug 빌드, Flash 기록과 Verify를 완료했다. 실제 보드에서 DMA 송신 완료 Callback이 Flag를 변경하고 _write()의 대기가 정상적으로 해제되어 UART 출력이 이어지는 것을 확인했다.

배운 점

  • __WFI()는 HAL 함수가 아니라 CMSIS-Core가 제공하는 CPU Intrinsic이다.
  • WFI는 Interrupt가 발생할 때까지 Processor 실행을 대기시킨다.
  • CPU가 깨어난 뒤에는 원하는 작업이 완료됐는지 Flag를 다시 검사해야 한다.
  • DMA 전송과 __WFI() 대기는 IRQ와 Callback이 정상적으로 연결되어 있어야 동작한다.

한 줄 정리

__WFI()는 DMA 송신 완료 Flag를 기다리는 동안 Cortex-M4가 불필요한 반복 연산을 하지 않고 Interrupt를 기다리게 한다.

STM32 자료구조: Queue와 Ring Buffer

배열 기반 FIFO와 Ring Buffer의 Index 순환, Full·Empty 처리를 학습한다.

기본 개념구현 목표핵심 코드동작 흐름Ring Buffer실행 결과배운 점

기본 개념

C 문자열은 문자 배열의 마지막 \0으로 끝난다. 따라서 배열의 전체 용량을 문자 데이터에 모두 쓰면 안 된다.

문자 입력
→
CommandBuffer
→
완성된 명령

구현 목표

  • 고정 길이 char 배열에 명령을 저장한다.
  • length로 다음 저장 위치를 관리한다.
  • \n에서 명령을 완료하고, Overflow는 거부한다.

핵심 코드

typedef struct
{
    char data[COMMAND_BUFFER_CAPACITY];
    size_t length;
} CommandBuffer;

command_buffer_append()는 글자를 추가한 뒤 항상 \0을 기록한다. 용량이 16이면 실제 Payload는 15글자까지다.

경계를 넘으면 기존 Buffer는 유지하고 COMMAND_BUFFER_FULL을 반환한다.

실행 결과

  • arm-none-eabi-gcc의 엄격한 문법·경고 검사를 통과했다.
  • MSVC Build Tools에서 호스트 CMake 빌드와 CTest를 실행했고, Ring Buffer의 FIFO·Wrap-around·Full·Empty 테스트를 포함한 1개 테스트가 통과했다.
  • STM32 보드 검증은 하지 않았다. 다음 단계에서 UART DMA 수신 흐름에 연결한다.

배운 점

고정 배열의 경계 검사와 \0 예약은 임베디드 문자열 처리의 기본 안전 장치다. Ring Buffer는 이 배열·Index·길이 관리 개념을 FIFO 데이터 흐름으로 확장한다. UART DMA와 Interrupt가 함께 접근할 때의 동시성 처리는 다음 학습 범위다.

한 줄 정리: Ring Buffer는 배열을 이동하지 않고 head와 tail을 순환시켜 고정 메모리에서 FIFO를 구현한다.

Ring Buffer

RingBuffer는 head를 다음 dequeue 위치, tail을 다음 enqueue 위치로 사용하고 count로 Empty와 Full을 구분한다.

data[tail] = value;로 저장한 뒤 tail = (tail + 1U) % RING_BUFFER_CAPACITY;로 Index를 순환시키고 count를 증가시킨다.
